Implemented architecture

RAS Connect Control Plane and Managed Endpoint Flow

RAS Connect links a locally authorized RAS Code environment to a signed-in cloud user, provisions a managed HTTPS/WSS endpoint for that environment, and brokers proof-bound remote connections. The local environment remains the authority that issues environment access credentials. The hosted relay stores links, reconciles managed endpoint resources, validates signed proofs, and delivers agent-activity notifications.

Client -> Relay: Clerk bearer or relay DPoP Relay -> Environment: relay-signed health and mint proofs Environment -> Relay: environment bearer plus signed activity proof Client -> Environment: environment access token plus DPoP

Security Invariant

A cloud identity is not an environment login. Remote access requires all of the following:

  • a Clerk-authenticated RAS Connect user;
  • an active relay link for that user and environment;
  • a DPoP proof key held by the remote client;
  • a relay-signed mint request accepted by the linked local environment; and
  • an environment-issued credential bound to the remote client's DPoP thumbprint.
The relay cannot mint an environment access token by itself. It can only ask the local environment to mint a short-lived bootstrap credential for an authorized cloud user.

During an honest connection flow, the relay cannot act as the remote client:

  • Normal environment API traffic passes through the relay Worker's shared path gateway and the endpoint's Durable Object. The relay can observe the DPoP-bound access token but cannot use it without the client's private proof key.
  • The one-time bootstrap credential and resulting environment access token are bound to the remote client's DPoP public-key thumbprint. Redeeming or using them requires request proofs signed by the corresponding private key, which stays on the client.
  • Relay-signed health and mint proofs are short-lived, audience-bound, scoped, and replay-guarded. They are accepted only by the narrow cloud endpoints, not as normal environment API credentials.
  • Environment health and mint responses are signed by the linked environment and bound to the request nonce, so a different process behind the connector cannot impersonate the linked environment.
The hosted relay remains a trusted mint broker: it holds the cloud-mint signing key. DPoP prevents credential reuse by the relay transport during an honest flow, but it does not make compromise of the relay signing authority harmless.

Product Boundaries

The local connector is built into the RAS Code server. It opens one authenticated outbound WebSocket and multiplexes relay HTTP and WebSocket traffic to loopback.

  • The relay Worker owns cloud links, Durable Object relay sessions, and notifications.
  • The environment server owns local sessions, environment keys, and access tokens.
  • The built-in connector exposes only the environment's loopback HTTP server.
  • Web and mobile clients connect through the shared managed-endpoint gateway after bootstrap.

Managed Endpoint Sessions

Each environment gets a deterministic endpoint ID. The shared gateway maps /e/:endpointId/* to one Durable Object session, while Postgres stores only the user/environment link and advertised endpoint.

1. Derive the endpoint The endpoint ID derives from the relay namespace and environment ID.
2. Connect the environment The built-in connector authenticates to the endpoint's Durable Object with the environment credential.
3. Proxy bounded traffic The session multiplexes capped HTTP streams and WebSocket connections to the validated loopback origin.
4. Replace or disconnect Relinking replaces the active connector. Unlinking revokes credentials and closes the session immediately.

Unlink Cleanup

Relay unlink revokes the user/environment link and closes its active relay session:

  • revoke the user's environment link; and
  • revoke the environment publication credential only after the final active link for that environment key disappears.
  • disconnect the environment's Durable Object relay session.

Local unlink stops the built-in connector and removes the locally persisted relay URL, issuer, linked user, environment publication credential, cloud-mint public key, connector config, and agent-activity preference.

Built-in Relay Operational Profile

Managed endpoints use one Durable Object and one authenticated outbound connector per linked environment. The connector is part of the RAS Code server; no separate connector or tunnel binary is installed.

  • Lifecycle: the server starts the connector when it reconciles an active link. Relinking replaces the existing connector, and unlink closes the Durable Object session immediately.
  • Origin: the connector forwards only to the linked environment server's validated loopback HTTP origin. Arbitrary upstream hosts and raw TCP origins are rejected.
  • Protocols: managed endpoints carry bounded HTTPS request/response streams and WSS connections. Remote clients use the normal environment HTTP APIs and authenticated WebSocket RPC transport through the relay.
  • Traffic shape: active remote sessions may keep WebSockets open and exchange terminal, agent, and UI updates. Inactive connectors keep one WebSocket open but do not generate application requests.
  • Capacity planning: Worker request usage grows with HTTP requests and WebSocket connection events, not with individual messages carried inside an accepted WebSocket. Durable Object duration and network transfer grow with active remote use.

SSRF and Relay Hardening

Risk Implemented control
A client asks the relay to forward to an arbitrary host. The environment and relay both accept managed relay origins only for loopback hosts and valid ports.
A forwarded request tricks local origin validation. The local link-proof handler requires an exact loopback request URL and rejects forwarded host or protocol headers.
A stored endpoint is replaced with an arbitrary external URL. The relay derives the endpoint from the environment ID and configured gateway. It does not accept a caller-selected managed endpoint URL.
A managed endpoint redirects relay egress elsewhere. Relay-to-environment status and mint requests set redirect handling to manual.
A process behind the connector returns attacker-controlled data. The relay verifies environment-signed health and mint responses against the linked environment public key, expected nonce, and request binding.
A stolen remote access token is replayed. Relay and environment access tokens are DPoP-bound; per-request proofs and replay guards are required.
The connector token leaks through process listings or shell parsing. The built-in connector receives its token through in-process runtime configuration; it is not passed to a child process or shell.
Managed endpoint IDs are routing identifiers, not credentials. The shared gateway preserves the public Host and path for DPoP validation, and environment access still requires a proof-bound credential issued by the linked environment.

Built-in Relay Connector

The connector runs inside the environment server. Runtime reconciliation starts it from the relay-issued connector URL and credential, restarts it after an unexpected close, and stops it when the link is disabled.

The binary relay protocol batches bounded control and payload frames. It multiplexes local HTTP requests and WebSocket sessions over one outbound WebSocket without a shell, downloaded binary, or inbound listener.

Relay Infrastructure

  • Cloudflare Worker for the hosted relay API and gateway.
  • Durable Objects for per-environment relay sessions.
  • Self-hosted Postgres database named ras-code-relay.
  • Production owns that database; every other stage gets its own ras-code-relay-<stage> database on the same server, reached through a Cloudflare Tunnel guarded by a Cloudflare Access application.
  • Cloudflare Hyperdrive with caching disabled and a constrained origin connection limit.
  • Cloudflare APNs delivery queue plus dead-letter queue.
  • A five-minute cron job that prunes expired DPoP replay rows.
  • PostHog OTLP traces endpoint and project token.

Implementation Checklist

  • Keep the relay cloud-mint private key hosted-only; install only its public key into environments.
  • Keep environment signing private keys local and persist keypair creation atomically.
  • Require a local relay:write session before linking or changing relay config.
  • Validate relay URLs as secure absolute HTTPS origins before sending credentials.
  • Require loopback-only connector origins on both sides of the link-proof boundary.
  • Resolve managed endpoint egress from linked endpoint IDs, not client-supplied URLs.
  • Disable redirects on relay-to-environment requests.
  • Validate environment-signed response proofs before consuming relayed responses.
  • Authenticate connector sessions and disconnect them immediately on unlink.
  • Revoke shared environment publication credentials only after the final active link disappears.
  • Redact and cap local agent failure details before publishing them externally.
